### P1 — 常驻预热播放器：真机一叫就死，且失败路径比遮罩窗口更长

**依据（真机 trace，插件自带）**：`<plugins>\_work\eva-warm-trace.log`，本机 2026-10-07 07:22:01
```
warm: started <Program Files>\PowerShell\7\pwsh.exe
warm: ready
warm: no ack for done
warm: player gone with done pending
warm: started …            （回落，重新起一个）
warm: ready
warm: player gone with ask pending
```
即：播放器起得来（约 0.7 s 到 `ready`），**一收到播放指令就退出**，每次都回落一次性进程。

**机制与量级**：回落前要等 `WARM_ACK_MS = 4000`（`index.js:167`，注释说「generous on purpose」）；而遮罩的全遮窗口是 `BOOT_MS 1750 + BOOT_HOLD_MS 520 = 2270 ms`（`src/boot-screen.js`），一次性路径实测第一声落在 **1389–1922 ms**。⇒ 走死管道的那一声 = 4000 + ~1400 ≈ **5400 ms**，远在遮罩撤掉之后。**这个特征本身就是它要治的病。**

**与宿主语义的关系**（基准证据）：`spawn` 不提供默认值、`cwd`/`graceMs` 必须显式、argv 不经 shell、**服务 dispose 会终止所有受管子进程并 await 退出**（`docs/subsystems/subprocess.md:15,93-131,277`）；「先注销监听表再杀进程」是官方的静止顺序（`docs/defensive-patterns.md`）。EVA 的 spawn 参数**完全合规**（`index.js:308-310` 显式 `cwd`/`stdio`/`graceMs`；`index.js:260,403` `terminate()`；`index.js:371-373` `await waitForExit()`），所以问题不在调用形式，而在「常驻子进程」这个选择本身的生存条件（子进程为什么在收到第一行后退出，未定位；可查方向：stdin 被 EOF 后 `[Console]::In.ReadLine()` 返回 `$null` → `break` → 退出）。

**建议（按顺序）**：
1. **先把失败成本压到遮罩窗口以内**：把等 ack 的上限从 4000 ms 降到 **≤ 800 ms**（播放器 0.7 s 内就已 `ready`，正常 ack 是毫秒级，800 ms 足够区分「活着但慢」与「已死」）。最坏情况变成 800 + 1400 ≈ 2200 ms < 2270 ms，症状被结构性消除，功能不变。
2. 再决定播放器的去留：若「子进程为何退出」不能在一次会话内定位，**建议直接删掉常驻播放器**（`index.js:137-464`，约 330 行）——遮罩已经把一次性路径的 1.4–1.9 s 延迟遮住了，它解决的问题已被遮罩解决，而它自己带来了 330 行状态机 + 一个静默失败模式 + 一个临时诊断文件（P2）。
   *理由*：删掉之后最坏情况就是「回到本轮之前的行为」；留着则是「多一套随时能把声音拖到 5 s 的机器」。

**归属**：`index.js` 此刻由**另一个会话**在改（见 §4），本轮不动。

### P2 — `trace()` 写死本机绝对路径，且每次声音决策同步写盘；连「无副作用」的测试也会写它

**为什么算问题**（不是洁癖）：
- 基准把「门禁不得写文件」写成了明文约定（endfield `ci.yml:51-53`：三个 `--check` 只做字符串比对，**不写文件、不起浏览器**）；EVA 自己也在 `tools/selfcheck.mjs` 的 `cli.18` 里禁掉了「本机绝对路径进入产物（`Users|DSH|Program|AppData|<user>|/Users/…`）」，但**那条断言只查 `client.js`，没有 `host.*` 版本**，于是 `index.js` 是这条不变量的漏洞面。
- `tools/check-sound-layer.mjs` 是本轮唯一「行为级、且宣称把 spawn 吞掉所以安全」的门；但 `apply()` 无条件调 `trace()`，**跑这道门会往包外的 `<plugins>\_work\eva-warm-trace.log` 追加内容** —— 一个测试带着隐藏的文件系统副作用，而且是同步写（`appendFileSync`）在声音决策的热路径上。

**建议（补丁已备好，等 `index.js` 归属明确后一并落地）**：`trace()` 改为 `process.env.EVA_SOUND_TRACE === '1'` 才写、路径取 `os.tmpdir()`；并在 `tools/selfcheck.mjs` 里加一条 `host.9`（照 `cli.18` 的写法查 `index.js`）。两处要一起做：只加断言会让门变红。

### P3 — `resolveSound()` 的 CWD 兜底

### P4 — 客户端逻辑活在生成器模板里，只能对生成物断言

**依据**：主题自己的客户端逻辑**没有独立 src 文件**，它内联在 `tools/build-client.mjs` 的 `body` 模板（约 252-315 行）里：`apply(ctx)`（`ctx.get('theme')` 早退；三个 `ctx.effect`：`theme.overrideTokens` / 注入 `<style data-plugin-css="…/theme.css">` / `mountBootScreen`）、随后 `applyPluginToggle(ctx)`、`exports.name/inject(['theme','remote','locale'])/apply`。
**对照基准**：endfield 的 house style 是把客户端拆成 `src/client/00-shell-head.js`…`99-shell-tail.js` 片段、`manifest.js` 定顺序、组装后先 `new vm.Script()` 验证再写盘（`scripts/lib/bundle-build.js`），产物与源码一一对应。
**现状代价**：自检只能钉生成物（`cli.8/cli.9/cli.11d` 都是对 `client.js` 做正则断言），改客户端逻辑要在**字符串模板**里写 JS —— 引号/转义/缩进都在一个更容易出错的位置（这正是 2026-10-06 那次「字面量反引号 → import failed」的土壤）。
**建议**：抽到 `src/client.js` 并逐字插值（照 `src/boot-screen.js` 的先例 + 本轮新加的构建期守卫）。属结构调整，**要你点头**。
