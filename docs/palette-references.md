# 三套参考色卡 · 原值对照

> **定位**：本文件是**参考色卡的取色台账**，只记录图上印了什么。它不是配色真源，也不参与生成链。
> 颜色真源仍然是 `tools/s2-palette.py`，其产物是 `out/s2-palette.json` 与 `src/tokens.json`。
> 本文件**不被任何工具读写**，改动它不会影响 `client.js` 或任何门禁。
>
> **数据来源与可信度**：图上印的是**十进制** RGB。下表逐格记「十进制原文 → hex 换算」。
> 来源 A = 用户 2026-10-06 当时发来的参考图原图（已不在工作区，本文件据其记录追溯）；
> 来源 B = 2026-10-08 用户重新发来的同三张图（知乎 @阿昊的科研日常 的科研配色卡），本文件按 B 重新 OCR 核对。
> **冲突时以 A 的既有文档记录为准**，凡 A/B 有出入处均已单列标注。
> 图表中的柱高与折线点位**没有**印刷数值，本文件一概不推断。
>
> 生成日期：2026-10-08。相关决策见 `docs/design.md` 的 D18（第三轮）与 D20（第四轮）。

| 2 | `R:063 G:160 B:063` | `#3FA03F` | 绿 | `--dsw-alias-state-success-primary` = `#49a948` | 明度重解 |

### OCR 的诚实边界

- 图 C 第 1 格 `B:156` 为最不确定项，另一种读法为 `136`；既有文档与第三轮取色一致支持 `156`。
- 图 C 第 2 格 `R:014` 的十位在缩图下偏窄，`014` 与 `074` 存在歧义；`G:180`、`B:156` 为高置信。
- 图 C 第 5 格 `B:085` 中间位最软，可能是 `095` 或 `088`；既有文档取 `085`。
- 三张图的柱高与折线点位均无印刷数值，本文件不记录、不推断。
- 图上数字带前导零（如 `086`、`063`、`029`），是印刷体的写法，按原文保留。
